# 💬 Telegram Bot Service (`telegram-bot`)

Тонкий интерфейсный клиент мобильного пейджера и согласований техподдержки на базе **aiogram 3.x**.

---

## 📌 Зона ответственности

* **Отвечает за:**
  * Получение Push-уведомлений о событиях заявок (новые заявки, комментарии, смены статусов) из персистентной очереди Redis Streams.
  * Гарантированную доставку (At-Least-Once): Consumer Group `bot_group`, подтверждение `XACK` и авто-перехват зависших сообщений через `XAUTOCLAIM` (PEL > 30 сек).
  * Интерактивные кнопки подтверждения оператором (Human-in-the-Loop) при установке принтеров.
  * Просмотр списка активных заявок инженера с пагинацией («Мои заявки»).
  * Безопасную авторизацию пользователей: пересылает учетные данные в Core API и **немедленно удаляет сообщение с паролем из чата**.

* **НЕ отвечает за:**
  * Хранение паролей и токенов (бот вообще не имеет доступа к БД).
  * Прямой опрос IntraService.
  * Исполнение инфраструктурных команд.

---

## 📡 Каналы связи

1. **HTTP REST (`telegram-bot` $\rightarrow$ `core-api`):**
   * Все запросы данных и авторизация выполняются через Core API с заголовком `X-Bot-Api-Key: <key>`.
2. **Redis Streams (`core-api / poller` $\rightarrow$ `telegram-bot`):**
   * Стрим: `stream:intraservice_events`
   * Consumer Group: `bot_group`
   * Потребитель: `bot_1`
   * Обработка сбоев: фоновый `xautoclaim` перехватывает недоставленные сообщения при перезапуске бота.

---

## 🚀 Запуск сервиса

### Через Docker Compose:
```bash
docker compose --profile with-bot up --build -d telegram-bot
```

### Локально для разработки:
```bash
cd telegram-bot
uv run python main.py
```

# План редизайна и модульного рефакторинга Web UI (intra-web)

> Документ сформирован по итогам архитектурного интервью (`/grill-me`) на основе задач из [`marks2.md`](../../../marks2.md).  
> Стандарт реализации: **Linear / Vercel Design Standard** ([`.agents/skills/frontend-design/SKILL.md`](../../../.agents/skills/frontend-design/SKILL.md)).

---

## 1. Цели и дизайн-принципы

1. **Полный отказ от эмодзи**: замена всех символов (`⚡`, `📚`, `🟢`/`🟡`/`🔴`, `🛡`, `✕`, `✓`) на строгие векторные SVG-иконки с единой толщиной штриха (`stroke-width="1.5"`) и нейтральные пульсирующие статус-доты.
2. **Монохромная дизайн-система кнопок**: переход от разноцветных ярких плашек (amber, indigo, blue) к строгой монохромной палитре (Primary: нейтрал черный/белый, Secondary: рамка `border-neutral-200` / `dark:border-neutral-750`, Ghost: прозрачный с hover). Цвет сохраняется **исключительно** у индикаторов реального статуса заявок.
3. **Геометрическая консистентность таблицы**: переход с плавающей `table-auto` на строгую сетку `table-fixed` с фиксированными предсказуемыми ширинами столбцов и одинаковым расстоянием между колонками.
4. **Увеличение масштаба интерфейса**: системный подъем размеров шрифтов и отступов (названия заявок 15px вместо 13.5px, строки таблицы 64–68px вместо 58px, бейджи и кнопки 12.5–13px вместо 10–11px, увеличенные поля в инспекторе).
5. **Модульная декомпозиция крупных компонентов**: разделение монолитного `TicketInspector.tsx` (1670+ строк) на изолированные подкомпоненты в папке `src/components/inspector/` и вынос модалок из `QueuePage.tsx` в `src/components/queue/`.

## 2. Спецификация по пунктам marks2.md

### Пункт 1. Консистентность кнопок и отказ от эмодзи
- **SVG-иконки:** В [`intra-web/src/components/Icons.tsx`](../../intra-web/src/components/Icons.tsx) добавляются:
  - `IconZap` (замена `⚡` в Rule Engine и тестах)
  - `IconBookOpen` (замена `📚` в RAG / Базе знаний)
  - `IconShield` (замена `🛡` в DLP / безопасности)
  - `IconCheck` (замена `✓`)
  - `IconX` (замена `✕`)
  - `IconArrowRight` (для кнопок переходов и действий)
- **Кнопки фильтрации очереди:**
  - Кнопки пакетных действий («Отменить все дубликаты», «Перенаправить все», «В ремонт все») приводятся к единому нейтральному стилю Secondary Button с SVG-иконкой и монохромным бейджем количества, без ярких сплошных заливок `bg-amber-600` или `bg-indigo-600`.
- **Контуры безопасности (Circuit):**
  - Замена текстовых эмодзи `🔴 RED`, `🟡 YELLOW`, `🟢 GREEN` на аккуратные бейджи с цветным статус-дотом (`w-1.5 h-1.5 rounded-full`) и монохромным текстом контура.

---

### Пункт 2. Столбец «Решение AI»
- **Заголовок:** В `thead` меняется стиль с акцентного `text-blue-600 dark:text-blue-400` на стандартный нейтральный `text-neutral-400 dark:text-neutral-500 uppercase tracking-wider text-[11.5px] font-semibold`.
- **Ячейка действия:**
  - Оформляется как аккуратная монохромная кнопка действия (h-7.5, px-2.5, rounded-lg, border border-neutral-200 dark:border-neutral-750) со статусным дотом целевого состояния и лаконичной SVG-стрелкой перевода.
  - Если заявка уже взята в работу (`statusId === 27`), отображается нейтральный статус-бейдж без кликабельного ховера.

---

### Пункт 3. Масштабирование интерфейса в целом
- **Таблица заявок:**
  - Высота строки увеличена с 58px до 64–68px (`h-[66px]`).
  - Основной заголовок/тема заявки: `text-[15px] font-bold` (вместо `text-[13.5px]`).
  - Метаданные заявителя и сервиса: `text-[13px]` (вместо `text-[12px]`).
  - Кнопки статуса и решения AI: `h-7.5 text-[12.5px]` (вместо `h-7 text-[11.5px]`).
  - Бейджи тегов (wi-fi, дубликат, печать): `text-[12px] py-0.5 px-2` (вместо `text-[10-11px]`).
- **Инспектор заявок (`TicketInspector`):**
  - Поля ввода (комментарий, списание минут) получают увеличенные отступы и комфортный кегль 14–15px.
  - Заголовки блоков и мета-информация заявителя масштабируются пропорционально.

---

### Пункт 4. Одинаковое расстояние между столбцами таблицы
Таблица переводится на класс `table-fixed` со строгим распределением ширин:

| Колонка | Ширина | Описание |
|---|---|---|
| **Чекбокс** | `w-12` (48px) | Выбор заявки для пакетных действий |
| **СТАТУС** | `w-40` (160px) | Текущий статус заявки с выпадающим списком смены |
| **РЕШЕНИЕ AI** | `w-44` (176px) | Рекомендованное действие / переход со статус-дотом |
| **ЗАЯВКА** | `w-auto` (flex/остаток) | Тема заявки, заявитель, бейджи тегов и вложений |
| **СЕРВИС** | `w-48` (192px) | Наименование сервиса каталога с усечением `truncate` |
| **ХОСТ** | `w-36` (144px) | Имя рабочей станции / IP с кнопкой копирования |
| **ИСПОЛНИТЕЛЬ** | `w-40` (160px) | ФИО ответственного инженера |
| **SLA** | `w-28` (112px) | Таймер и индикатор дедлайна с сортировкой |

Каждая ячейка получает единый горизонтальный отступ `px-3.5`, что обеспечивает математически одинаковое визуальное расстояние между столбцами на любых разрешениях.

### Пункт 5. Модульный рефакторинг

#### Декомпозиция `TicketInspector.tsx` (1671 строка)
Создается каталог `intra-web/src/components/inspector/`:
1. `InspectorHeader.tsx` (~120 строк) — Draggable-ручка ресайза, бейдж ID заявки с копированием, кнопка разворота во всю ширину, меню быстрых действий и кнопка закрытия.
2. `RequesterCard.tsx` (~130 строк) — Карточка заявителя: ФИО, телефон, кабинет/подразделение, список хостов с кнопками копирования и онлайн-статусом.
3. `DiagnosticsSection.tsx` (~160 строк) — Блок сетевой экспресс-диагностики (Ping, SMB:445, WinRM:5985) с поддержкой нескольких ПК и индикацией задержки RTT.
4. `AiTriageCard.tsx` (~140 строк) — Карточка вердикта Rule Engine / AI Hub, уровень уверенности, статус контура безопасности (RED/GREEN/YELLOW дот) и кнопка «Переанализировать».
5. `AiSummarySection.tsx` (~110 строк) — Сворачиваемая карточка AI-суммаризации истории переписки.
6. `RagMatchesSection.tsx` (~120 строк) — Список релевантных исторических решений из базы знаний pgvector со сходством и кнопкой вставки.
7. `WorkerActionsSection.tsx` (~130 строк) — Автоматизация через `execution-worker` (удаленный перезапуск очереди печати, диагностика).
8. `AttachmentsSection.tsx` (~110 строк) — Галерея вложений, миниатюры скриншотов и вызов модального окна просмотра (Lightbox).
9. `ReplyActionForm.tsx` (~180 строк) — Форма ответа заявителю: выбор шаблона, переключатель «Ответ заявителю / Заметка», авторесайз textarea, списание минут, кнопки «В работу», «Отменить» и «Выполнить».
10. `CommentsTimeline.tsx` (~140 строк) — Хронологическая лента переписки и системных изменений.
11. `TicketInspector.tsx` (~180 строк) — Чистый координирующий контейнер, агрегирующий состояние и подкомпоненты.

#### Декомпозиция `QueuePage.tsx` (1440 строк)
Создается каталог `intra-web/src/components/queue/`:
1. `SmartBatchModal.tsx` (~200 строк) — Модальное окно смарт-пакетного выполнения заявок с предпросмотром шаблонов и списания.
2. `BulkConfirmModal.tsx` (~120 строк) — Модальное окно массового перевода статусов.
3. `QueueFiltersBar.tsx` (~140 строк) — Панель переключения вкладок (Все, Дубликаты, Редиректы, В ремонт, Wi-Fi) с монохромными кнопками пакетных действий.

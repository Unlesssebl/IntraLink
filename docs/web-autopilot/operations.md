# Эксплуатация движка автоматизации ADR 0006

## Режим работы

В runtime действует только полуавтоматический режим `ASSISTED`. `FULL_AUTO`, shadow/canary, dual-write и совместимый scenario API отсутствуют. Poller наблюдает очередь и обновляет watermark, но не анализирует и не исполняет заявки.

Штатный поток:

1. Оператор открывает заявку и явно нажимает «Анализировать».
2. Проверяет CaseFrame, тип обращения, workflow, недостающие факты и ActionPlan.
3. При необходимости отдельно исправляет тип обращения или параметры ActionPlan. Любая коррекция создаёт новую версию плана и запускает новый preflight.
4. Назначает сервисную учётную запись техническим исполнителем заявки.
5. Подтверждает конкретный ActionPlan.
6. Worker сверяет snapshot и все hash-привязки, проверяет назначение, статус, lease и preflight, затем исполняет одну capability.

Назначение сервисной учётной записи без явного approval не создаёт инфраструктурных изменений.

## Состояния, требующие внимания

- `ambiguous`, `unknown`, `degraded`: оператор выбирает тип обращения или переводит заявку в ручную работу.
- `awaiting_facts`: требуется получить перечисленные факты; допускается не более двух циклов уточнения.
- `awaiting_diagnostics`: причина ещё не доказана, техническая команда не сформирована.
- `needs_review`: выполнение завершилось `failed` или `unknown_outcome`; заявку нельзя закрывать до ручной проверки.
- `printer_executor_unavailable`: установка принтера недоступна и не должна публиковать фиктивный успех.

## Пароли и секреты

Для создания пользователя provisioning-сервис записывает логин в `Field1488`, пароль в защищённое поле `Field1489`. Пароль не попадает в модель, публичные или скрытые комментарии, CaseFrame, планы, feedback, результаты команд и журналы.

## Offline-приёмка

Перед атомарной заменой версии профилей, extraction или workflow выполните:

```powershell
.venv\Scripts\python.exe -m core.automation.replay --dataset-root datasets/automation/v1 --min-accuracy 1.0
.venv\Scripts\python.exe -m pytest
.venv\Scripts\ruff.exe check .
cd web
npm run build
```

Replay не обращается к IntraService, LDAP, WinRM или LLM и не является shadow-режимом. Новая версия активируется только после закрытой offline-приёмки.

## Ошибка исполнения

При неподтверждённом результате worker оставляет заявку «В работе», останавливает ActionPlan и сохраняет санитизированный технический результат. Автоматический повтор потенциально необратимой capability запрещён, если исход предыдущей попытки неизвестен.

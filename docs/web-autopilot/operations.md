# Настройка и запуск

Автопилот по умолчанию выключен. Сначала примените миграции к чистой PostgreSQL командой `alembic upgrade head` и убедитесь, что API, Poller, `command-worker`, Redis и Windows execution-worker доступны.

Poller обходит активные циклы устойчивыми страницами. Размер страницы задаётся `AUTOPILOT_POLL_BATCH_SIZE` (по умолчанию `200`), число параллельных сверок — `AUTOPILOT_MAX_CONCURRENCY` (по умолчанию `5`). Увеличивать параллелизм следует только после проверки лимитов IntraService.

В конфигурации задайте ID сервисной учётной записи `assistant` через `INTRASERVICE_SERVICE_USER_ID`. Проверьте ID статусов IntraService: открыта `31`, требует уточнения `35`, в работе `27`, выполнена `29`, отменена `30`, закрыта `28`. Триггером служит назначение этой учётной записи исполнителем открытой заявки.

Перед включением настройте и активируйте в PostgreSQL шаблоны:

- `printer_ip_clarify` и `pc_offline` со статусом `35`;
- `ticket_timeout_cancel`, `ticket_not_relevant`, `autopilot_unsupported_cancel` и `autopilot_execution_failed_cancel` со статусом `30`;
- `resolved_standard` со статусом `29`.

Web UI покажет отсутствующий, пустой, некорректный по статусу или переменным шаблон и не позволит включить автопилот. Тексты отмены изменяйте через существующее административное управление шаблонами.

В политиках Command API выберите режим для `diagnose_host`, `install_printer` и `apply_triage`. Значение `confirm` оставляет изменяющую команду в ожидании инженера; `auto` разрешайте отдельно только после проверки Windows-исполнителя и шаблонов. Автоматический повтор установки принтера и обновления заявки запрещён независимо от режима policy.

После проверки откройте настройки Web UI и включите общий выключатель. Назначения, замеченные во время выключения, сохраняются и продолжатся только после повторной проверки статуса и назначения Poller-ом.

Состояние видно в очереди и карточке заявки. При `system_error` проверьте фактический результат последней команды и причину в истории, затем явно возобновите цикл либо переключите его в ручной режим. Приостановленный инженером цикл общий выключатель не возобновляет. Завершение и отмена оставляют `assistant` среди исполнителей.

## Контроль пилота

До пилота выполните [staging-приёмку](staging-acceptance.md). Во время пилота контролируйте `/metrics`:

- неопубликованный outbox старше 60 секунд требует проверки command-worker и Redis;
- outbox старше 5 минут либо рост очереди служит основанием выключить автопилот;
- цикл в `running` или `waiting_approval` без движения более 15 минут требует разбора;
- `waiting_answer` может оставаться активным до заданного срока 72 часа;
- каждый новый `system_error` разбирается до повторного включения изменяющих действий в `auto`.

Начальная политика `install_printer` и `apply_triage` для пилота — `confirm`. Один необъяснённый повтор установки, комментария, трудозатрат или смены статуса останавливает пилот.

## Новая база данных

Перенос и совместимость со старой БД не требуются. В течение пилота историю `TicketRun`, команд и событий не удалять автоматически. Хранить её не менее 365 дней; перед последующим сокращением срока сначала сделать проверяемый backup через `scripts/backup-postgres.ps1` и проверить восстановление командой `scripts/verify-postgres-restore.ps1`.

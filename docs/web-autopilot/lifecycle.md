# Спецификация поведения: два режима и жизненный цикл

Статус: действующая целевая спецификация. Уточнения пограничных случаев от 2026-09-06 требуют реализации и приёмки; их наличие в документе не означает поддержки кодом. Назначение продукта — в [концепции](product-concept.md), следующий этап — в [карте доведения](concept-alignment.md), настройка — в [инструкции](operations.md).

## Состояние и запуск

PostgreSQL хранит цикл, режим, шаг, ожидания, результаты, события и связь с командами. Redis служит доставке и кэшу. Статус IntraService, состояние цикла и состояние команды различаются. Для заявки допускается один активный цикл; смена режима его не заменяет.

- Ассистент — сервисная учётная запись IntraService, указанная в админ-панели; `assistant` — условное имя. Источник ID — проверенная конфигурация этой же учётной записи в PostgreSQL, а Redis хранит восстанавливаемый кэш. Сравнение по имени запрещено; другие исполнители не создают дополнительных циклов.
- Новый автопилотный цикл требует статуса «Открыта», назначенного ассистента и включённого автопилота. Неизвестный статус запрещает запуск.
- При выключенном автопилоте назначение сохраняется как ожидающее. При включении условия проверяются заново; завершённое назначение не повторяется.
- Основание назначения сохраняется и дедуплицируется. Новое основание — подтверждённое снятие и повторное назначение по истории IntraService либо наблюдаемой сервером смене исполнителей. При отсутствии надёжных свидетельств требуется явный запуск из Web UI.
- При первом обнаружении открытой заявки с ассистентом без прежнего цикла допускается одно начальное основание. Повторный опрос его не обновляет.
- Переоткрытие само по себе не запускает автопилот. Новый явный запуск требует статуса «Открыта» и остальных условий допуска.
- Ручная работа допускается в известных незавершённых статусах без назначения ассистента. Завершённые заявки доступны для просмотра; продолжение требует переоткрытия.

ID берутся из конфигурации: сейчас «Открыта» — `31`, «Требует уточнения» — `35`, «В работе» — `27`, «Выполнена» — `29`, «Отменена» — `30`, «Закрыта» — `28`. Конечные статусы запрещают новые автоматические действия.

## Управление и остановка

Режим — ручной или автопилот. Состояние — ожидает запуска, выполняется, ожидает ответа, ожидает согласования, приостановлен, системная ошибка или завершён. Завершённый цикл хранит исход: выполнено, отменено либо прекращено внешним изменением статуса.

В ручном режиме инженер выбирает диагностику и действия, редактирует ответ и обновляет заявку. Изменяющие действия из Web UI связаны с общим циклом и проходят серверные проверки конфликтов, доступа и согласований.

| Событие | Поведение |
|---|---|
| Выбран ручной режим или снят ассистент | Запретить новые автоматические шаги; после завершения начатого действия разрешить ручные изменения. Переход в Web UI сам не снимает ассистента |
| Администратор выключает автопилот | Приостановить автоматические циклы, отменить ещё не начатые связанные команды. Ручные циклы продолжаются |
| Автопилот снова включён | Возобновить только циклы, остановленные исключительно общим выключателем, после проверки актуальности |
| Инженер приостанавливает цикл | Требуется явное возобновление; общий выключатель эту паузу не снимает |
| Заявка получила конечный статус | Прекратить цикл, запретить новые изменения, сохранить результат начатого действия |
| Возврат из ручного режима в автопилот | Явное действие; ассистент назначен, автопилот включён, статус допускает текущий шаг. Завершённый цикл не возобновлять |

Начатый внешний вызов не считается мгновенно отменённым. До выяснения результата конфликтующие изменения заблокированы. После паузы шаг планируется по актуальным данным; прежнее согласование не переносится на изменённые параметры.

## Первый сценарий и исходы

Установка сетевого принтера: проверить реквизиты ПК и принтера → запросить недостающие данные → диагностировать → выполнить разрешённую установку → проверить результат → обновить заявку. Нельзя заявлять о тестовой печати или ином результате, которого исполнитель не подтвердил.

Выбранные значения первой версии: не более двух запросов уточнения за цикл; каждый ожидает ответа 72 часа с подтверждённой отправки. Посторонние и собственные комментарии таймер не продлевают. Перед отменой повторно проверяются новые ответы. Пауза срок не сбрасывает; после возобновления проверяются ответы и истечение срока.

| Причина | Действие |
|---|---|
| Не хватает реквизитов либо ПК недоступен | Статус `35`, конкретный запрос; расходует один из двух запросов уточнения |
| Нет ответа 72 часа | Отмена шаблоном `ticket_timeout_cancel` |
| Заявитель явно отказался | Отмена шаблоном `ticket_not_relevant` |
| Сценарий не поддерживается | Пауза с причиной; статус и исполнителей не менять |
| Подтверждён неверный раздел | Редирект: статус `30`, шаблонный комментарий и действующая ссылка на целевой сервис Helpdesk; через общие политики и Command API |
| Уточнения исчерпаны | Отмена отдельным шаблоном только при отсутствии необходимых данных от заявителя; не смешивать с неподдерживаемостью или неспособностью системы разобрать содержательный ответ |
| Известный окончательный отказ установки, результат проверен | Отмена шаблоном `autopilot_execution_failed_cancel` без утверждения, что проблема решена |
| Сбой API/БД/исполнителя, неизвестный результат, неверная конфигурация | Системная ошибка цикла; статус заявки не менять, автоматически оператору не передавать |
| Действие запрещено либо согласование отклонено/истекло | Приостановить цикл; это не основание отмены обращения |
| Установка подтверждена | Статус `29`, шаблон завершения с подтверждёнными фактами |

Предел времени команды берётся из действующей политики Command API. Изменяющие операции после ошибок и таймаутов автоматически не повторять: сначала выяснить фактический результат. Диагностика использует конечные лимиты существующего исполнителя. Исчерпание лимитов не создаёт новый цикл.

## Шаблоны, политики и надёжность

- Отмена — статус `30` с обязательным комментарием из активного шаблона PostgreSQL. Новые шаблоны настраивает администратор до включения сценария. Текст не генерируется моделью. Отсутствующий шаблон или незаполненная переменная останавливают цикл; fallback «принято в работу» запрещён.
- В истории сохранить причину, ключ шаблона и снимок отправляемого текста. Изменение шаблона не меняет согласованную команду. При частичном внешнем успехе сверить статус и комментарий до повторной отправки.
- Политика действия определяет `auto`, `confirm` или `disabled`, включая отмену через `apply_triage`. Установка и изменение заявки по умолчанию требуют подтверждения. Администратор может явно разрешить автоматическое исполнение действий первого сценария; общего обхода ограничений риска нет.
- Разрешение AUTO не разрешает автоматические повторы. При `confirm` Web UI показывает подготовленные статус и текст.
- Перед внешним изменением проверить режим, статус, исполнителей, полномочия и актуальность цели. Повторное событие не создаёт повторной команды или комментария.
- После отмены и успеха оставлять ассистента назначенным. Системная ошибка видна в Web UI с причиной; продолжение требует проверки результата и явного возобновления либо ручного режима.
- Закрытие вкладки и рестарт не меняют ход работы. При недоступной БД новые изменения запрещены; UI показывает недоступность или устаревание данных.

## Пограничные случаи: принятые решения

### Поддержка сервисов и порядок решения

Источник допуска — явная серверная связь «ID сервиса → включённые сценарии» в PostgreSQL, управляемая администратором. Название сервиса, назначение ассистента и оценка AI не заменяют эту связь. Сервис поддерживается только при наличии реализованного включённого сценария; доступность инфраструктуры проверяется отдельно. Этот механизм целевой, а не утверждение о наличии готового реестра в коде.

Если назначена заявка вне настроенного покрытия, предметное исполнение не начинается, заявка не отменяется; причина видна в UI. Внутри поддерживаемого сервиса неизвестный тип запроса также приводит к паузе. Редирект является общей предварительной проверкой заявок, допущенных по сервису, и может указывать на сервис вне покрытия автопилота.

Приоритет: актуальность и полномочия → проверка нескольких независимых просьб → подтверждённый дубликат → корректность раздела и редирект → предметный сценарий. Это согласованное правило продукта для существующих проверок; нельзя реализовать вторую независимую цепочку решений в UI. Запрет политики действует на любом шаге.

### Редирект, дубликаты и неоднозначность

| Случай | Решение |
|---|---|
| Правильный раздел неясен | Один конкретный запрос уточнения в пределах общего лимита. Сходства текста или самооценки AI недостаточно для отмены |
| Получен содержательный ответ, но система всё ещё не может выбрать раздел | Пауза для проверки; не считать это отсутствием ответа или неподдерживаемостью по вине заявителя |
| Целевой сервис удалён, ссылка неверна или доступ заявителя не подтверждён | Не отменять исходную заявку; приостановить редирект с причиной и проверить маршрут |
| Несколько независимых просьб относятся к разным сервисам | Не исполнять часть и не отменять всё автоматически. Попросить выделить отдельные обращения и указать, какой запрос остаётся в текущем. Не создавать дочерние заявки автоматически |
| Несколько шагов решают одну проблему | Считать единым сценарием, а не требовать разделения по числу действий |
| Есть действующая основная заявка, полностью покрывающая запрос | Отмена дубликата с комментарием и ссылкой на основную имеет приоритет над предложением создать новое обращение |
| Основная заявка закрыта либо покрывает только часть просьбы | Не отменять как дубликат; проверить повторную проблему и непокрытую часть |
| Заявитель повторил обращение после редиректа | Сопоставить доступную историю и новые факты. Если подтверждён тот же маршрут и тот же запрос — пауза вместо повторной автоматической отмены. При отсутствии надёжной связи не угадывать по одному сходству |
| В истории обнаружен маршрут A → B → A | Блокировать очередной редирект и показать конфликт маршрутизации |

Ссылки строятся из доверенного каталога Helpdesk, а не из текста модели. Доступ сервисной учётной записи не доказывает доступ заявителя. Использовать достоверные сведения о доступности либо административно подтверждённый маршрут для соответствующей аудитории; при отсутствии такого подтверждения автоматический редирект приостановить. Не отправлять заявителю ссылки на недоступные ему основные заявки и не раскрывать их содержимое.

Все уточнения расходуют один общий бюджет цикла: максимум два успешно отправленных запроса, по 72 часа каждый. Нельзя заново выдавать этот бюджет при смене шага или переанализе. Отсутствие ответа и явный отказ обрабатываются по общей таблице исходов. Ошибка классификатора после достаточного ответа не является исчерпанием уточнений.

### Конкурентные изменения и внешние результаты

Перед изменением повторно читать существенные сведения: раздел, статус, исполнителей, цель действия и новые сообщения. Изменение любого влияющего на решение факта отменяет актуальность предложения и согласования, но не стирает черновик оператора. Два оператора не могут подтвердить разные исполнения одного шага: конфликт версии должен возвращать актуальное состояние, а не повторять действие.

| Случай | Решение |
|---|---|
| Ответ пришёл перед отменой по таймауту | Повторно проверить историю непосредственно перед изменением; релевантный ответ отменяет основание таймаута |
| Ответ пришёл после последней проверки или уже после отмены | Зафиксировать поздний ответ и показать «Требует внимания» без автоматического переоткрытия, новой команды или нового цикла |
| Комментарий отправлен, но статус не обновлён, либо наоборот | Сохранить частичный результат; сверить обе части по истории и фактическому состоянию. Не показывать полный успех и не отправлять всё заново |
| Неизвестно, приняла ли внешняя система запрос | Остановить изменяющие действия до сверки. Если результат доказать нельзя — явная проверка инженером |
| Автопилот выключен во время установки | Запретить новые шаги, сохранить фактический результат начатого. Не считать внешний вызов мгновенно отменённым и не отправлять автоматическое завершение после выключения |
| Заявку закрыли извне во время исполнения | Сохранить результат команды, но не менять конечный статус и не публиковать новое автоматическое завершение |
| После паузы появился новый сценарий или исправлена настройка | Явное возобновление и новый анализ; изменение конфигурации не запускает массово приостановленные заявки |

Повторная проверка не гарантирует атомарности во внешнем API. Где доступна условная запись по версии — использовать её. В остальных случаях фиксировать прочитанное состояние и сверять результат после вызова; не обещать полное отсутствие гонок. Для обнаружения поздних ответов нужна ограниченная сверка завершённых циклов: первые 72 часа после автоматической отмены, с сохранённой позицией истории и без автоматических изменений. Это отдельная задача реализации; вне этого окна сохраняются обычный просмотр истории и ручной разбор.

При частичном успехе разрешается явное завершение только доказанно невыполненной части после повторных проверок и применимого согласования. Новая команда ссылается на исходную; слепой автоматический повтор запрещён.

### Кто ответил и как это влияет на ожидание

Автор сообщения определяется ID. Автоматически учитывать релевантный ответ заявителя или явно уполномоченного представителя, если такое полномочие подтверждается системой. Собственные, служебные и посторонние комментарии не сбрасывают таймер. Сообщение инженера не становится ответом заявителя автоматически; инженер может явно принять содержащиеся в нём данные с записью авторства и повторной проверкой реквизитов. Неизвестное авторство не трактуется как согласие.

Каждая пауза имеет конкретную причину, видимое следующее действие и сохраняет статус обращения, если отдельное изменение не предусмотрено выше. «Требует внимания» — представление в Web UI, а не автоматическое назначение оператору.

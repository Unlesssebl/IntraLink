# Спецификация поведения: два режима и жизненный цикл

Статус: действующая спецификация. Назначение продукта — в [концепции](concept.md), порядок работ — в [плане](implementation-plan.md), настройка — в [инструкции](operations.md).

## Состояние и запуск

PostgreSQL хранит цикл, режим, шаг, ожидания, результаты, события и связь с командами. Redis служит доставке и кэшу. Статус IntraService, состояние цикла и состояние команды различаются. Для заявки допускается один активный цикл; смена режима его не заменяет.

- Ассистент определяется настроенным ID учётной записи, а не именем. Другие исполнители не создают дополнительных циклов.
- Новый автопилотный цикл требует статуса «Открыта», назначенного ассистента и включённого автопилота. Неизвестный статус запрещает запуск.
- При выключенном автопилоте назначение сохраняется как ожидающее. При включении условия проверяются заново; завершённое назначение не повторяется.
- Основание назначения сохраняется и дедуплицируется. Новое основание — подтверждённое снятие и повторное назначение по истории IntraService либо наблюдаемой сервером смене исполнителей. При отсутствии надёжных свидетельств требуется явный запуск из Web UI.
- При первом обнаружении открытой заявки с ассистентом без прежнего цикла допускается одно начальное основание. Повторный опрос его не обновляет.
- Переоткрытие само по себе не запускает автопилот. Новый явный запуск требует статуса «Открыта» и остальных условий допуска.
- Ручная работа допускается в известных незавершённых статусах без назначения ассистента. Завершённые заявки доступны для просмотра; продолжение требует переоткрытия.

ID берутся из конфигурации: сейчас «Открыта» — `31`, «Требует уточнения» — `35`, «В работе» — `27`, «Выполнена» — `29`, «Отменена» — `30`, «Закрыта» — `28`. Конечные статусы запрещают новые автоматические действия.

## Управление и остановка

Режим — ручной или автопилот. Состояние — ожидает запуска, выполняется, ожидает ответа, ожидает согласования, приостановлен, системная ошибка или завершён. Завершённый цикл хранит исход: выполнено, отменено либо прекращено внешним изменением статуса.

В ручном режиме инженер выбирает диагностику и действия, редактирует ответ и обновляет заявку. Изменяющие действия из Web UI связаны с общим циклом и проходят серверные проверки конфликтов, доступа и согласований.

| Событие | Поведение |
|---|---|
| Выбран ручной режим или снят ассистент | Запретить новые автоматические шаги; после завершения начатого действия разрешить ручные изменения. Переход в Web UI сам не снимает ассистента |
| Администратор выключает автопилот | Приостановить автоматические циклы, отменить ещё не начатые связанные команды. Ручные циклы продолжаются |
| Автопилот снова включён | Возобновить только циклы, остановленные исключительно общим выключателем, после проверки актуальности |
| Инженер приостанавливает цикл | Требуется явное возобновление; общий выключатель эту паузу не снимает |
| Заявка получила конечный статус | Прекратить цикл, запретить новые изменения, сохранить результат начатого действия |
| Возврат из ручного режима в автопилот | Явное действие; ассистент назначен, автопилот включён, статус допускает текущий шаг. Завершённый цикл не возобновлять |

Начатый внешний вызов не считается мгновенно отменённым. До выяснения результата конфликтующие изменения заблокированы. После паузы шаг планируется по актуальным данным; прежнее согласование не переносится на изменённые параметры.

## Первый сценарий и исходы

Установка сетевого принтера: проверить реквизиты ПК и принтера → запросить недостающие данные → диагностировать → выполнить разрешённую установку → проверить результат → обновить заявку. Нельзя заявлять о тестовой печати или ином результате, которого исполнитель не подтвердил.

Выбранные значения первой версии: не более двух запросов уточнения за цикл; каждый ожидает ответа 72 часа с подтверждённой отправки. Посторонние и собственные комментарии таймер не продлевают. Перед отменой повторно проверяются новые ответы. Пауза срок не сбрасывает; после возобновления проверяются ответы и истечение срока.

| Причина | Действие |
|---|---|
| Не хватает реквизитов либо ПК недоступен | Статус `35`, конкретный запрос; расходует один из двух запросов уточнения |
| Нет ответа 72 часа | Отмена шаблоном `ticket_timeout_cancel` |
| Заявитель явно отказался | Отмена шаблоном `ticket_not_relevant` |
| Сценарий не поддерживается или уточнения исчерпаны | Отмена шаблоном `autopilot_unsupported_cancel` с соответствующей причиной |
| Известный окончательный отказ установки, результат проверен | Отмена шаблоном `autopilot_execution_failed_cancel` без утверждения, что проблема решена |
| Сбой API/БД/исполнителя, неизвестный результат, неверная конфигурация | Системная ошибка цикла; статус заявки не менять, автоматически оператору не передавать |
| Действие запрещено либо согласование отклонено/истекло | Приостановить цикл; это не основание отмены обращения |
| Установка подтверждена | Статус `29`, шаблон завершения с подтверждёнными фактами |

Предел времени команды берётся из действующей политики Command API. Изменяющие операции после ошибок и таймаутов автоматически не повторять: сначала выяснить фактический результат. Диагностика использует конечные лимиты существующего исполнителя. Исчерпание лимитов не создаёт новый цикл.

## Шаблоны, политики и надёжность

- Отмена — статус `30` с обязательным комментарием из активного шаблона PostgreSQL. Новые шаблоны настраивает администратор до включения сценария. Текст не генерируется моделью. Отсутствующий шаблон или незаполненная переменная останавливают цикл; fallback «принято в работу» запрещён.
- В истории сохранить причину, ключ шаблона и снимок отправляемого текста. Изменение шаблона не меняет согласованную команду. При частичном внешнем успехе сверить статус и комментарий до повторной отправки.
- Политика действия определяет `auto`, `confirm` или `disabled`, включая отмену через `apply_triage`. Установка и изменение заявки по умолчанию требуют подтверждения. Администратор может явно разрешить автоматическое исполнение действий первого сценария; общего обхода ограничений риска нет.
- Разрешение AUTO не разрешает автоматические повторы. При `confirm` Web UI показывает подготовленные статус и текст.
- Перед внешним изменением проверить режим, статус, исполнителей, полномочия и актуальность цели. Повторное событие не создаёт повторной команды или комментария.
- После отмены и успеха оставлять ассистента назначенным. Системная ошибка видна в Web UI с причиной; продолжение требует проверки результата и явного возобновления либо ручного режима.
- Закрытие вкладки и рестарт не меняют ход работы. При недоступной БД новые изменения запрещены; UI показывает недоступность или устаревание данных.

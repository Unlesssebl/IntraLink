# 📦 Сущности IntraService API

Этот справочник описывает структуры данных внешнего API IntraService, которые используются в логике шлюза **Core API Gateway** и Telegram-бота. 

---

## 1. Задача / Заявка (`Task`)

Используется при получении списка задач через эндпоинт `GET /api/v1/tasks`, а также фоновым воркером для отслеживания изменений.

### Основные поля задачи

| Поле | Тип | Описание | Пример значения |
| :--- | :---: | :--- | :--- |
| `Id` | Integer | Уникальный номер (ID) заявки. | `1054` |
| `Name` | String | Тема / Название заявки. | `"Проблема с доступом"` |
| `Created` | String | Дата и время создания. | `"2026-06-04 15:40:00"` |
| `StatusId` | Integer | ID текущего статуса задачи. | `1` |
| `StatusName` | String \| null | Название текущего статуса задачи. | `"Новая"` |
| `ServiceId` | Integer | ID услуги / сервиса. | `10` |
| `ServiceName` | String \| null | Название услуги. | `"Почта"` |
| `CreatorId` | Integer \| null | ID заявителя в IntraService. | `9891` |
| `CreatorName` | String \| null | Имя заявителя. | `"Иванов Иван"` |
| `Description` | String \| null | Полное текстовое описание заявки. | `"Не могу зайти в почту..."` |
| `ExecutorIds` | String \| null | Список ID исполнителей, разделенный запятыми. | `"9891,9892"` |

> [!IMPORTANT]
> Обратите внимание, что поле `ExecutorIds` возвращается внешней системой в виде текстовой строки с разделителем-запятой (например, `"9891,9892"`), а не в виде JSON-массива. Обработчик воркера выполняет парсинг этой строки самостоятельно с помощью разделения по запятой.

---

## 2. История задачи (`TaskLifetime`)

Используется для отслеживания изменений статусов и добавления комментариев. Возвращается эндпоинтом `GET /api/v1/tasks/{task_id}/lifetime`.

### Основные поля события истории

| Поле | Тип | Описание | Пример значения |
| :--- | :---: | :--- | :--- |
| `Date` | String | Дата и время события. | `"04.06.2026 15:45:00"` |
| `Editor` | String \| null | Имя пользователя, который внес изменения. | `"Петров Петр"` |
| `Comments` | String \| null | Текст добавленного комментария (если был добавлен). | `"Задача принята в работу."` |
| `StatusId` | Integer \| null | ID нового статуса задачи (если статус менялся). | `2` |

---

## 3. Ограничения Core API Gateway

> [!WARNING]
> Core API Gateway на текущий момент поддерживает **только операции чтения** (проксирование `GET` запросов) для задач, истории изменений и справочника статусов.
> 
> Создание заявок (`POST /api/task`) и изменение статусов/комментариев через REST API в текущей версии шлюза **не поддерживаются**. Все изменения должны проводиться через интерфейс IntraService или другие каналы.

## 🎯 Ключевые цели презентации

1. Продемонстрировать переход от «ручного перекладывания тикетов» к **автоматизированной фабрике обработки инцидентов**.
2. Показать окупаемость и измеримый бизнес-эффект: **-94% MTTR**, **-96% время реакции**, **160+ сэкономленных часов инженеров в месяц (1 FTE)**.
3. Снять риски информационной безопасности: **100% On-Premise, изоляция данных, шифрование Fernet, Zero Cloud Leakage**.
4. Продемонстрировать реальные экраны веб-пульта (/admin), работу RAG-поиска, обнаружение дубликатов, генерацию ответов и сетевую диагностику.

## ❓ Вопросы и ответы (Q&A Cheat Sheet)

| Вопрос руководства / ИБ | Рекомендуемый ответ спикера |
|---|---|
| **Уходят ли данные пользователей в облачные сервисы (OpenAI/ChatGPT)?** | **Нет.** Вся система развернута строго в закрытом On-Premise контуре (Docker-контейнеры с PostgreSQL 16 pgvector и локальной моделью Ollama Qwen2.5). Нулевая утечка данных (Zero Cloud Leakage). |
| **Что происходит при сетевом сбое во время автоматизации Active Directory?** | Действует принцип **Verified Execution Only**. Статус тикета переводится в «Выполнена» только при получении кода возврата `0`. При любой ошибке заявка остается в статусе «В работе» с уведомлением инженера. |
| **Как обновляется векторная база знаний RAG?** | При закрытии каждого тикета в Helpdesk алгоритм FastEmbed автоматически строит векторные эмбеддинги и индексирует решение в pgvector через команду `/sync`. |
| **Каковы требования к серверным ресурсам?** | Система ультра-эффективна: Core API, PostgreSQL, Redis и локальная квантованная модель Qwen2.5:1.5B стабильно работают на 4 vCPU и 8 ГБ RAM без необходимости дорогих видеокарт GPU. |

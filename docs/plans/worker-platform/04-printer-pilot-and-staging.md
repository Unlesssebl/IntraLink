# Инкремент 4: Эталонный InstallPrinterHandler и SMB Staging

Статус: запланирован  
Зависимости: [Инкремент 2](02-worker-sdk-and-runner.md), [Инкремент 3](03-durable-workflow-and-plan-hash.md)  
Целевые компоненты: `execution-worker/handlers/install_printer.py`, `shared/printers.py`, `execution-worker/worker.py`

---

## 1. Цель инкремента

Реализовать эталонный обработчик установки принтеров `InstallPrinterHandler`, устраняющий все исторические уязвимости:
- Обход Kerberos Double-Hop через безопасный SMB Staging драйверов с проверкой SHA-256 и ограниченными ACL.
- Перенос WMI bootstrap WinRM строго в фазу `prepare` после approval.
- Безопасное восстановление WinRM в `cleanup` только при доказанном владении.
- Полный запрет на Generic Fallback.
- Точная верификация очереди, порта и версии драйвера.

---

## 2. Задачи к реализации

### 2.1. Фаза 1: `validate`
- Проверка входных данных через Pydantic-модель:
  - `pc_name`: нормализация через `shared.normalizer.normalize_pc_name` (валидный NetBIOS/FQDN).
  - `printer_name`: проверка на допустимые символы.
  - `connection_type`: `tcpip` или `usb`.
  - `printer_ip`: валидный IPv4/IPv6 для сетевых принтеров.

### 2.2. Фаза 2: `preflight` (Строго Read-Only)
- **Запрещено изменять состояние хоста!**
- Проверка доступности хоста по сети (Ping, TCP порт 135 / 5985).
- Запрос состояния службы `Spooler` через CIM/WMI (`Get-CimInstance Win32_Service -Filter "Name='Spooler'"`).
- Запрос состояния службы `WinRM` (получение `State` и `StartMode` без запуска!).
- Для TCP/IP: проверка доступности порта `9100` на IP-адресе принтера.
- Поиск точного профиля в KB принтеров с фиксацией версии и SHA-256 драйвера.
- Если профиль не найден — немедленная остановка с кодом `driver_profile_not_found` (никаких Generic fallback!).
- Возврат снимка `preflight_evidence`.

### 2.3. Фаза 3: `prepare` (Строго после Approval)
- Если на этапе preflight зафиксировано, что WinRM был выключен (`State != 'Running'`):
  - Сохраняются исходные `State` и `StartMode`.
  - Генерируется уникальный `ownership_token`.
  - Через WMI/RPC (порт 135) служба переводится в `demand` и запускается.
  - Сохраняется время запуска.

### 2.4. Фаза 4: `execute` (SMB Staging & Local PnpUtil)
1. **Локальный SMB-кеш:** Воркер с доменными правами вычитывает INF-пакет из разрешенного корня шары (`allowlist_smb_roots`), проверяет SHA-256 и цифровую подпись.
2. **Staging на целевой ПК:** Пакет копируется через сессию WinRM в изолированный каталог `C:\Windows\Temp\_driver_staging\<command_id>\` с правами доступа только для `SYSTEM` и локальных администраторов.
3. **Проверка хеша на клиенте:** Сверка SHA-256 скопированного пакета на целевом ПК.
4. **Установка драйвера:** Вызов `pnputil.exe /add-driver <local_inf_path> /install`.
5. **Создание порта:** `Add-PrinterPort` с явными параметрами через `-ArgumentList`.
6. **Регистрация очереди:** `Add-Printer` с точным именем драйвера из профиля.

### 2.5. Фаза 5: `verify`
- Проверка по точному совпадению:
  - Существование очереди печати с запрошенным именем.
  - Совпадение порта печати с созданным.
  - Совпадение имени и версии драйвера.
- Сбор `execution_evidence` и сохранение в результат.

### 2.6. Фаза 6: `cleanup`
- Гарантированное удаление каталога стейджинга `C:\Windows\Temp\_driver_staging\<command_id>\`.
- Восстановление службы WinRM:
  - Выполняется **только если** служба была запущена этим `attempt`, `ownership_token` валиден, и текущая конфигурация не разошлась с ожидаемой.
  - Если замечен дрейф (сторонние сессии или вмешательство GPO) — откат прекращается, создается operational alert.
  - Невозможность зачистки не маскирует результат, а создает предупреждение оператору.

## 3. Критерии приемки (Definition of Done)

1. Успешный E2E-тест установки принтера от валидации до финализации.
2. Тест: при отсутствии драйвера в KB установка отклоняется до изменения хоста.
3. Тест: на целевой машине не остается временных файлов стейджинга.
4. Тест: если WinRM был исходно выключен, после завершения команды служба корректно возвращается в исходное состояние.
5. Тест: при сбое копирования драйвера WinRM немедленно очищается, а команда переходит в `needs_review`.

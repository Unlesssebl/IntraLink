# Workflow: Пакетный триаж заявок (`/triage`)

Выполняет сквозной пакетный анализ входящей очереди заявок 1-й линии (Filter ID: 984) с сетевой диагностикой ПК, семантическим поиском решений в pgvector и интерактивным согласованием действий. Поддерживает разбор как всей очереди, так и фильтрацию по человеческому номеру сервиса/раздела каталога (`01`..`16`).

## Варианты вызова:
- `/triage` — разбор всей стопки заявок из фильтра 1-й линии (по умолчанию 5 заявок).
- `/triage <номер_сервиса>` (например, `/triage 2`, `/triage 03`, `/triage 6`) — сканирование заявок **только указанного сервиса** со всеми его подсервисами.
- `/triage <номер_сервиса> <лимит>` (например, `/triage 2 10`) — выборка до N заявок по указанному разделу.

## Шаги выполнения:
1. **Проверка статуса БД:** Выполнить команду `uv run python helpdesk_tool.py check-db` в каталоге `helpdesk_agent/`. Если PostgreSQL не запущен, выполнить `start-db`.
2. **Получение стопки заявок:** 
   - Если указан сервис: выполнить `uv run python helpdesk_tool.py batch --service <НОМЕР_ИЛИ_ИМЯ> --limit <N>`.
   - Если сервис не указан: выполнить `uv run python helpdesk_tool.py batch --limit <N>`.
3. **Презентация карточек:** Вывести лаконичные 4-строчные карточки заявок без технического шума (Заголовок со статусом и сетью хоста, Заявитель с контактами, Проблема, Проект ответа).
4. **Интерактивное согласование (Human-in-the-Loop):** Открыть модальное окно `ask_question` с мультивыбором (`is_multi_select: true`) для подтверждения оператором.
5. **Применение решений:** После выбора применить подтвержденные задачи через `uv run python helpdesk_tool.py apply <ID> --status <STATUS> --comment "<ТЕКСТ>"` и автоматически проиндексировать закрытые тикеты в базу знаний.

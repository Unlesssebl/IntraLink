# 🧠 Память и контекст проекта Intralink (`GEMINI.md`)

Файл постоянной контекстной памяти для AI-агента Antigravity. Содержит ключевые инварианты инфраструктуры, правила вызова команд и доменную специфику IntraService.

---

## 🏗️ 1. Инфраструктура и окружение (Docker / Базы данных)

* **PostgreSQL (pgvector):**
  * Контейнер: `intralink_postgres`
  * Пользователь: `postgres`
  * База данных: `intraservice`
  * Подключение:
    ```bash
    docker exec intralink_postgres psql -U postgres -d intraservice -c "<SQL>"
    ```
  * Таблица базы знаний RAG: `task_knowledge_base` (векторный индекс HNSW на поле `embedding`, размерность 1024).

* **Redis:**
  * Контейнер: `intralink_redis` (порт в контейнере: 6379, хост: 6380)
  * Токен аутентификации воркера: ключ `worker:service_auth_b64` (зашифрован Fernet, расшифровывается через `decrypt_token`).
  * Кэш каталога услуг: ключ `worker:service_catalog` (TTL 24 часа).
  * Кэш аналитических отчётов нагрузки: ключи `reports:load:month:{year}_{month}` (TTL 30 дней для закрытых месяцев, 5 минут для текущего). Динамический API: `/api/v2/reports/load` и `/api/v2/reports/export`.

* **Core API (Legacy v1 vs Architecture v2):**
  * В ветке `feat/v2-vertical-slice-architecture` проект переходит на модульный монорепозиторий v2 согласно `docs/architecture/v2-architecture-blueprint.md` (ADR 0004).
  * Директория `core-api/` является устаревшим кодом (Legacy v1) и используется только как донор логики для нового бэкенда `api/`.
  * Новый бэкенд разворачивается в `api/` с вертикальными срезами (`api/src/features/*`).
  * Для доменной специфики IntraService (раздел 2) и Helpdesk (раздел 4) правила остаются неизменными.

## 🌐 2. Специфика IntraService API

* **Базовый URL:**
  * `settings.INTRASERVICE_URL` уже оканчивается на `/api` (например, `https://servicedesk-pub.corporate.loc/api`).
  * При конструировании относительных путей **не дублировать `/api`**: использовать `/service`, `/task`, `/tasklifetime` и т.д.

* **Типы заявок (`/api/tasktype`):**
  * Запрос детальной информации `GET /api/tasktype/{tasktypeid}` **всегда требует обязательный параметр `serviceid`** (например, `/api/tasktype/4?serviceid=40`), иначе API возвращает `400 Bad Request`.
  * Типы заявок раздела 05 (Directum):
    * Сервисы `40, 41, 233, 234` -> Тип `4` (`Directum`: инциденты, договоры, тендеры, установка; поля `1015, 1016, 1017, 1519`).
    * Сервисы `55, 232` -> Тип `1018` (`Заявка на пользователя DIRECTUM`: онбординг, доступы; поля `1121-1135, 1180, 1488, 1489, 1521`).

* **Ограничения каталога услуг (`/api/service`):**
  * Контроллер сервисов IntraService API работает **строго в режиме чтения (`GET`)**.
  * Запросы `POST` и `PUT` возвращают `405 Method Not Allowed`.
  * Создание, переименование, настройка прав и структуры сервисов производятся **исключительно через веб-интерфейс администратора** (`Настройка` ➔ `Каталог услуг` ➔ `Сервисы`).
  * Единственные доступные POST-методы: `/api/serviceuser` и `/api/servicecompany` (привязка пользователей/компаний к сервисам).

* **Документация:**
  * Полный справочник IntraService API v4.47 находится локально в каталоге:
    `docs/external/intraservice_api/IntraService_API_Index.md`
  * Перед исследованием новых эндпоинтов **всегда сверяться с локальным индексом**.

## ⚡ 3. Стандарты выполнения скриптов (Windows / pwsh)

* **Запрет на сложные однострочники через `-c "..."`:**
  * Из-за особенностей парсинга PowerShell вложенные кавычки, обратные слэши, f-строки вида `f'{t.get(\"...\")}'` и регулярные выражения вроде `(\d+)` ломаются шеллом до передачи в Python.
* **Каноничный способ запуска сложных проверок:**
  * Создавать временный скрипт или передавать через конвейер:
    ```powershell
    Get-Content ./core-api/scratch_check.py | docker exec -i intralink_core_api python
    ```

## 🏢 4. Бизнес-доменная модель Helpdesk

* **Раздел 09: Электронная подпись (ЭЦП) и банк-клиенты:**
  * **Банк-клиенты (ВТБ, Сбербанк, ГПБ, ПСБ):** строго финансы, бухгалтерия и казначейство. Не смешивать с логистикой или ж/д перевозками.
  * **СБИС (Saby) и корпоративный ЭДО:** общекорпоративная система (бухгалтерия, кадры/КЭДО, сбыт, снабжение, отчётность ФНС/СФР). Ни в коем случае не сводить только к логистике.
  * **АС ЭТРАН (РЖД):** выделенная ж/д система (отгрузка вагонов, накладные ГУ-27/29, логистика холдинга ТЭМПО). Рассматривать как отдельный специализированный сервис.
  * **Государственные порталы и торговые площадки:** Госуслуги (ЕСИА), ФТС (таможня), Честный Знак, Росприроднадзор, тендерные площадки (44-ФЗ, 223-ФЗ, B2B-Center), МЧД.
  * **Регламентные ограничения:**
    1. ИТ-отдел **не выпускает личные ЭЦП на физлиц** (направлять в коммерческие УЦ).
    2. Ошибки обмена и выгрузки **внутри 1С** направлять в раздел `06. Вопросы по 1С`.

* **Раздел 05: DIRECTUM и тендерная площадка B2B:**
  * **Согласование договоров, счетов и документов (ID: 40):** согласование договоров, маршруты, подписание, зависшие задачи документооборота.
  * **Закупки и тендеры (ID: 41):** тендерные листы, площадка B2B-Center, закупки, протоколы выбора победителя.
  * **Выдача доступа, сброс паролей (ID: 232):** учетные записи пользователей Directum (TaskType `1018` с кадровой анкетой).
  * **Установка Directum (ID: 233):** инсталляция толстого клиента Directum, настройка рабочего места заявителя.
  * **Технические проблемы (ID: 234):** ошибки клиента Directum, сбои проводника, падение служб.

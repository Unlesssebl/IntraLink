# IntraService Helpdesk Skill (AGY-Native Batch Triage & RAG)

Этот навык обучает AI-агента Antigravity (AGY) автономно, безопасно и с максимальной скоростью вести очередь заявок технической поддержки в IntraService от лица инженера **Беликова Алена** (ООО «АйТи ТЭМПО», тел. `49-87`, АБК-3, каб. 112).

Система строго соблюдает **корпоративный брендбук и минималистичный стиль без эмодзи (Zero-Emoji Policy)**, рассчитывает **Confidence Score (0.00 - 1.00)** для защиты от слепого пакетного одобрения (Rubber Stamping), поддерживает **контекст переписки (Thread-Aware)** и ведет **журнал аудита решений (Feedback Loop)**.

Подробное руководство по сценариям: [`docs/services/helpdesk-cli/WORKFLOWS.md`](../../../docs/services/helpdesk-cli/WORKFLOWS.md).

## Интерактивные триггеры и Слэш-команды

AI-агент мгновенно распознает как слэш-команды, так и естественный язык:

| Слэш-команда | Фразы на естественном языке | Действие агента |
|---|---|---|
| `/triage` `[сервис]` `[N]` | `разбери 2 сервис`, `триаж 03`, `пачка 5`, `разбери 1С` | Пакетный триаж очереди 1-й линии (Filter 984). Поддерживает фильтрацию по номеру раздела (`01`..`16`) и лимиту N |
| `/redirect` `[N]` `[сервис]`<br>`/triage [N] [сервис] /redirect` | `отмени редиректы 01`, `заявки на перенаправление`, `триаж 04 /redirect` | Поиск и пакетная отмена заявок, поданных не в тот раздел каталога, с переводом в Статус 30 («Отменена») и маршрутизацией |
| `/duplicates` `[N]`<br>`/dedup` `[N]` | `найди дубликаты`, `почисти дубли`, `проверь дубли заявок` | Поиск и пакетная отмена заявок-дубликатов с линковкой на основную задачу (Master ticket) |
| `/newuser <ID>` | `создай пользователя <ID>`, `создай уз <ID>` | Автоматическое создание учетной записи в Active Directory с генерацией пароля и закрытием заявки (Статус 29: **Выполнена**) |
| `/wlan <ID>` | `выдай wifi <ID>`, `вайфай <ID>` | Автоматическая выдача Wi-Fi доступа в AD (WLAN-WORKNET) и закрытие заявки |
| `/services` | `каталог сервисов`, `номера разделов` | Список корневых разделов каталога услуг с номерами (`01`..`16`) для фильтрации |
| `/task <ID>` | `детали <ID>`, `покажи карточку <ID>` | Детальный просмотр задачи с кастомными полями, историей, контекстом переписки и RAG |
| `/diag <ХОСТ/IP>` | `проверь <ХОСТ>`, `пинг <IP>` | Сетевая диагностика (ICMP Ping, DNS, SMB:445, WinRM:5985) |
| `/screen <ID>` | `скриншот <ID>`, `покажи вложение <ID>` | Скачивание и анализ изображения ошибки через `view_file` |
| `/kb <запрос>` | `поиск в базе <запрос>`, `как решали <...>` | Семантический поиск исторических решений в pgvector |
| `/sync` | `синхронизируй базу`, `обнови знания` | Выгрузка закрытых тикетов в векторную базу FastEmbed |
| `/db` | `проверь базу`, `статус бд` | Проверка и автозапуск PostgreSQL + pgvector (Tier 1) |

## 🛠 Доступные CLI-команды (`helpdesk-cli/helpdesk.py`)

```bash
# 0. Проверка и автоматический запуск PostgreSQL + pgvector
uv run python helpdesk-cli/helpdesk.py check-db
uv run python helpdesk-cli/helpdesk.py start-db

# 1. ПАКЕТНЫЙ РАЗБОР СТОПКИ ЗАЯВОК (Основной рабочий режим)
# Все разделы очереди:
uv run python helpdesk-cli/helpdesk.py batch --limit 5

# Фильтрация по конкретному номеру раздела каталога (например 2 - ПО, 3 - Оргтехника, 6 - 1С):
uv run python helpdesk-cli/helpdesk.py batch --service 2 --limit 5
uv run python helpdesk-cli/helpdesk.py batch --service 03 --limit 5
uv run python helpdesk-cli/helpdesk.py batch --service 6 --limit 5

# 1.1. ПОИСК И ОТМЕНА ЗАЯВОК НА РЕДИРЕКТ (/redirect)
uv run python helpdesk-cli/helpdesk.py redirect --limit 5
uv run python helpdesk-cli/helpdesk.py redirect --service 01 --limit 5
uv run python helpdesk-cli/helpdesk.py batch --service 04 --limit 5 --redirect

# 1.2. АВТОМАТИЧЕСКОЕ СОЗДАНИЕ ПОЛЬЗОВАТЕЛЕЙ В AD
uv run python helpdesk-cli/helpdesk.py create-user <ID_ЗАЯВКИ>
uv run python helpdesk-cli/helpdesk.py create-user <ID_ЗАЯВКИ> --dry-run
uv run python helpdesk-cli/helpdesk.py wlan <ID_ЗАЯВКИ>

# Список доступных номеров разделов каталога:
uv run python helpdesk-cli/helpdesk.py services

# 2. Детальная карточка конкретной заявки
uv run python helpdesk-cli/helpdesk.py task <ID_ЗАЯВКИ>

# 3. Сетевая диагностика ПК / IP
uv run python helpdesk-cli/helpdesk.py diagnose <ИМЯ_ПК_ИЛИ_IP>

# 4. Просмотр и скачивание вложений (скриншоты ошибок)
uv run python helpdesk-cli/helpdesk.py attachment <ID_ЗАЯВКИ>

# 5. Поиск по RAG-базе исторических решений
uv run python helpdesk-cli/helpdesk.py search-kb "<ТЕКСТ_ПРОБЛЕМЫ>"

# 6. Умная синхронизация выполненных заявок в базу знаний
uv run python helpdesk-cli/helpdesk.py sync-kb --limit 50

# 7. Применение решения (после подтверждения оператора!)
uv run python helpdesk-cli/helpdesk.py apply <ID> --status <STATUS_ID> --comment "<ТЕКСТ>" [--expenses <МИН>]
```

## 📋 Статусы IntraService
- `27` — **В работе** (стандартное принятие задачи)
- `35` — **Требует уточнения** (ПК не в сети, нет ответа заявителя)
- `48` — **Ожидание устройства** (аппаратный ремонт, замена диска, принести системный блок в 112 каб.)
- `30` — **Отменена** (неверный раздел каталога услуг, перенаправление)
- `29` — **Выполнена** (Wi-Fi предоставлен, инцидент закрыт)
- `31` — **Открыта** (первичный статус новой заявки)

## Основной бизнес-процесс: Интерактивный пакетный триаж (Batch Triage)

0. **Фильтр очереди:** Обрабатываются заявки **строго и только** из фильтра «1 Линия» (Filter ID: `984` / `FILTER_ID`). Обработка заявок вне этого фильтра запрещена.
1. **Формат ссылок:** Все ссылки на заявки в веб-интерфейсе формируются строго: `[#<ID>](https://servicedesk.corporate.loc/Task/View/<ID>)`.
2. **Проверка и запуск БД (Tier 1 pgvector):** Перед началом разбора очереди агент проверяет доступность PostgreSQL (`check-db`). Если БД не запущена, агент предупреждает оператора (*«[WARN] PostgreSQL остановлен, запускаю базу данных...»*) и выполняет `start-db` для перевода RAG в промышленный режим Tier 1.
3. **Запрос очереди:** При вводе `/triage` (или `/triage 2`, `/triage 03`, `«Разбери 6 сервис»`), агент запускает `batch` с флагом `--service <НОМЕР>` (если указан) и `--limit <N>`.
4. **Минималистичная презентация карточек (Zero-Emoji Policy / Linear-стиль):**
   Агент выводит лаконичные карточки по каждой заявке с четким монохромным форматированием:
   - **Заголовок:** `[№] [#ID](https://servicedesk.corporate.loc/Task/View/<ID>) | [STATUS: <СТАТУС>] | [HOST: <Имя ПК> - ONLINE <RTT>ms] | [CONF: <SCORE>] | [КОНТУР]`
     - Маркеры контура: `[RED / ON-PREM]`, `[SANITIZED]`, `[OPEN]`
     - Маркер уверенности: `[CONF: 0.94]` либо `[LOW CONF: 0.64 / ТРЕБУЕТСЯ ПРОВЕРКА]` (при score < 0.80)
   - **Заявитель:** `ФИО (каб. <Кабинет> | тел. <Телефон>) | <Дата>`
   - **Раздел:** `<Название сервиса>`
   - **Вложения:** Если есть вложение: `[ATTACHMENT: <filename> -> вызовите 'скриншот N']`
   - **Ответ заявителю:**
     `Ответ заявителю:`  
     `«<Точный текст ответа по корпоративным шаблонам инженера Беликова Алена>»`
5. **Текстовые шорткаты согласования (Human-in-the-Loop):**
   - Агент завершает сообщение понятным списком быстрых шорткатов (`все`, `1, 2, 4`, `детали N`).
   - Модальный инструмент `ask_question` не вызывается, чтобы исключить блокировку экрана и гарантировать вывод карточек.
6. **Обработка быстрых шорткатов оператора:**
   - **`все` / `+` / `ок`** $\rightarrow$ Агент применяет только проверенные заявки с `confidence_score >= 0.80`. Заявки с низким скором пропускаются с предупреждением и требованием точечного подтверждения.
   - **`1, 2, 4`** $\rightarrow$ Агент применяет рекомендации только для выбранных номеров.
   - **`детали N`** $\rightarrow$ Агент запускает `task <ID>` и показывает полную историю и переписку (Thread-Aware).
   - **`скриншот N`** $\rightarrow$ Агент запускает `attachment <ID>`, скачивает файл и просматривает его через `view_file`.
   - **`шаблон <имя> для N`** $\rightarrow$ Агент переключает шаблон (`hardware_repair`, `1c_issue`, `printer_issue`, `wifi_access`, `pc_offline`, `wrong_service`).
   - **`для N напиши: <текст>`** $\rightarrow$ Агент применяет кастомный текст комментария оператора.
7. **Журнал аудита и Feedback Loop:** Каждое применение решения логируется в таблицу `triage_audit_log` с расчетом коэффициента правки оператора (`diff_ratio`). Просмотр журнала аудита доступен командой `review-feedback`.
8. **Непрерывное автообучение:** Каждое закрытое решение (`status 29/30`) автоматически индексируется в базу знаний RAG.

## Каталог адаптивных шаблонов (`templates.json`)
* **`hardware_repair` (Статус 48):** *«Приносите системный блок / ноутбук в АБК 3, 112 каб. на диагностику, обслуживание и настройку. О времени визита вы можете написать в комментариях к этой заявке.»*
* **`pc_offline` (Статус 35):** *«Не вижу ПК {pc_name} в сети.\n1. Убедитесь в корректности имени ПК;\n2. Перезагрузите компьютер;\n3. Проверьте подключение сетевого кабеля.\nПожалуйста, напишите в комментариях к заявке, когда ПК будет включен и доступен в сети.»*
* **`1c_issue` (Статус 27):** *«Ваша заявка принята в работу. Выполняется проверка информационной базы и очистка кэша 1С на рабочей станции {pc_name}.\nЕсли у вас возникнут дополнения, пожалуйста, напишите в комментариях к этой заявке.»*
* **`printer_issue` (Статус 27):** *«Ваша заявка принята в работу. Выполняется проверка сетевого порта и очереди печати принтера на рабочей станции {pc_name}.\nЕсли у вас возникнут дополнения, пожалуйста, напишите в комментариях к этой заявке.»*
* **`wifi_access` (Статус 29):** *«Доступ к Wi-Fi предоставлен. Используйте логин и пароль от вашей учетной записи на ПК. Инструкцию приложил. Если возникнут сложности, напишите в комментариях к заявке или подходите в АБК-3, каб. 112.»*
* **`wrong_service` (Статус 30):** *«Заявка отменена, т. к. создана не в подходящем разделе. Требуется оставить заявку в подходящем разделе: {target_service}.\nЕсли у вас остались вопросы, пожалуйста, напишите в комментариях к этой заявке.»*
* **`duplicate_task` (Статус 30):** *«Заявка отменена, т. к. является дубликатом заявки #{master_task_id}. Работы ведутся в рамках основной заявки. Если у вас есть дополнения по проблеме, пожалуйста, оставьте комментарий в заявке #{master_task_id}.»*

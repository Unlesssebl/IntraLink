# 🖨️ Printer Worker & Orchestration Skill

Этот навык описывает правила и архитектурные особенности микросервиса `printer-worker` при автоматической установке драйверов и подключении принтеров на рабочих станциях домена.

---

## ⚙️ Архитектурные инварианты

1. **Динамическое включение WinRM (WMI Bootstrap):**
   - На удаленной станции WinRM настраивается «на лету» через WMI (DCOM/RPC) непосредственно перед началом установки.
   - По завершении установки (успешной или аварийной) WinRM гарантированно деактивируется оркестратором для снижения поверхности сетевых атак.

2. **Сетевая проверка Fail-Fast перед подтверждением:**
   - Перед переводом задачи в статус `WAITING_APPROVAL` обязательно проверяются:
     * Наличие обязательных полей (`connection_type`, `target_pc`, `driver_info`);
     * Сетевая доступность целевого ПК (Ping, порт 445 SMB);
     * Сетевая доступность МФУ (при типе подключения `tcpip` порт 9100).
   - Если хост недоступен — задача сразу переводится в статус «Требует уточнения» с комментарием заявителю.

3. **Тихий режим для системных сбоев:**
   - Ошибки разделяются на *пользовательские* (выключен ПК, нет пинга) и *системные* (сбой SMB-шары драйверов, ошибка RPC).
   - При системных сбоях комментарий пользователю не отправляется, статус «Требует уточнения» не выставляется (задача остается в текущем статусе для разбора администратором).

4. **Динамическое UPN-форматирование для SMB:**
   - Учетные данные приводятся к формату `username@domain.com` во избежание сбоев `STATUS_LOGON_FAILURE` в Linux-контейнерах.

5. **Распределенные блокировки (Distributed Locks):**
   - Индексация драйверов по SMB защищена Redis-локом (`indexer:status` с TTL) от параллельных запусков.

6. **Нормализация пользовательского ввода (Sanitization):**
   - Кириллические омоглифы и лишние IP-адреса нормализуются на этапе `redis_listener` до передачи в оркестратор.
